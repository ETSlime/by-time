## レンダリングシステム

###  Forward Rendering
- Forward パスベースの描画。
- 複数のレンダリングパスに分離：
  - メインパス（Main Pass）
  - シャドウマップパス（Shadow Pass）
- 対応オブジェクトタイプ：
  - 静的モデル（Static Mesh）
  - スキンメッシュ（Skinned Mesh）
  - インスタンシング描画オブジェクト

###  シャドウマップシステム（CSM 対応）
- 最大4層までのカスケードシャドウマップに対応。
- LightViewProj 行列を自動計算。
- texel 単位での snap による精度調整。
- Debug 用 Frustum 可視化。
- ShadowMapRenderer が VS / Layout を自動切替。
- オブジェクトの AABB を用いたレベル選択と冗長アップロード対応。

## インスタンシング描画

###  対応オブジェクト
- 草（風で揺れる）
- 木（揺れ無し）
- 岩・花・茂み（今後対応予定）

###  技術的詳細
- オブジェクトごとに別の `InstanceBuffer` と `InputLayout` を使用。
- 草の頂点データは `GrassVertex` で、風揺れ用の `Weight` を保持。
- インスタンスごとにスケール・回転行列・位置情報を `InstanceData` に格納。
- アップロード方式：`D3D11_USAGE_DYNAMIC + Map/Unmap`。
- カリング済みデータは `SimpleArray<InstanceData>* visibleInstances` に格納。

###  LOD（Level of Detail）対応
- LOD レベルごとにバッファを分割管理。
- 各フレームでカメラとの距離から LOD レベルを自動決定。
- `DrawIndexedInstanced()` を LOD ごとに実行。

## モデル読み込みとアニメーション管理

###  FBXLoader の実装
- 自作の `FBXLoader` により `.fbx`（ASCII形式）ファイルを直接パース。
- 頂点情報（Position, Normal, UV, Tangent 等）、インデックス、マテリアルを抽出。
- スケルトン構造：各ボーンに対する階層構造・親子関係を保持。
- アニメーションデータ：
  - ボーンごとのキーフレーム（位置・回転・スケール）を取得。
  - 複数のアニメーションクリップを `AnimClip` として格納。
  - 各 `AnimClip` に対して長さ、ループ属性、ブレンド用補間情報を保持。
- アニメーションクリップはアニメーションステートマシンに連携され、状態に応じて切り替え・ブレンド処理を実施。


###  状態遷移設計
- `AnimationStateMachine<State>` テンプレート構造。
- 列挙型 State による高速ステート管理。
- 各ステートにアニメーションデータ + 遷移条件 + 遷移後ステート + ブレンド時間保持。

###  遷移条件の実装
- 関数ポインタ（`bool (Character::*)() const`）で条件分岐。
- `GetNextState(ISkinnedMeshModelChar* character)` にキャラ参照を渡すことで、内部状態による判断可能。

###  補間・ブレンド
- 直線補間：`XMVectorLerp`（位置）
- 球面線形補間：`XMQuaternionSlerp`（回転）
- ブレンド中のボーンマトリクス合成処理あり。

## パーティクルシステム

###  完全 GPU ベースの構成
- 全ての処理を Compute Shader により実装。
- 4段階パイプライン：
  - `EmitCS`: 粒子の生成
  - `UpdateCS`: 粒子の位置・速度・寿命更新
  - `SortCS`: 描画順用ソート（アルファ対応）
  - `DrawIndirect`: `IndirectArgs` による描画

###  粒子管理方式
- `FreeList` 構造：死亡した粒子の回収と空き SlotID の再利用。
- `g_FreeListConsumeUAV.Consume()` により動的割り当て。
- `spawnRate` による生成速度の統一制御。

###  機能一覧
- **フレームアニメーション（Texture Sheet / Flipbook）**
- **Cone 形状からの発射エリア制御**
- **Lifetime に応じたスケーリング・色変化**
- **SoftParticle 対応（カメラ距離によるフェード）**
- **DrawIndirect + GPU ソートによる高効率バッチ描画**

## 地形と衝突判定

### 🧱 Octree 加速構造
- Octree を使用して地形三角形を空間分割し、指定領域内の三角形検索を高速化
- 各ノードは AABB、子ノード、および対応する三角形インデックスを保持
- 動的構築、遅延構築、非同期構築に対応し、大規模シーンの初期化時におけるメインスレッドの停止を軽減
- 地形領域検索、Ray Casting、オブジェクト配置などの CPU 側空間検索に利用可能

### 🧊 Sparse Voxel Grid
- **Sparse Voxel Grid** によるシーン三角形の空間インデックスを提供し、実際にジオメトリを含むアクティブなボクセルのみを保持
- **64 ビット Morton 符号**を使用して空間データを管理し、ソート、ページングインデックス、二分探索によって候補三角形を高速に検索
- シーン三角形を `StructuredBuffer` にアップロードすることで、Compute Shader から GPU 上で直接空間検索および高精度な衝突判定を実行可能
- 汎用的なシーンジオメトリ検索構造として、パーティクルシミュレーション、Ray / Triangle 衝突判定、軌道予測、レーザー衝突判定などの上位システムから再利用可能
- 流体シミュレーションにおける Voxel Grid 衝突処理の詳細については、独立した **Water Simulation** 技術ドキュメントを参照

### 🌾 草の配置アルゴリズム
- 草は地形全体へ均一に配置するのではなく、ランダムな Cluster 単位で生成
- 各 Cluster にランダムな範囲を設定し、Octree を使用して範囲内の候補地形三角形を検索
- Ray テストによって各草インスタンスの正確な地面配置位置を取得
- 三角形の法線に基づいて草の向きを自動調整
- 地形の傾斜を判定し、傾斜が大きすぎる場所では草を生成しない

## エフェクトシステム

### FireEffectRenderer（炎 + 煙）
- Texture Sheet による炎のフレームアニメーションを再生
- 煙は粒子システムで描画し、単独表示と炎との同時表示に対応
- 共通の `Update()` / `Draw()` インターフェースを提供
- Additive、AlphaBlend などのブレンドモードに対応
- SoftParticle と Flipbook アニメーションのブレンドに対応

### 粒子と地形の衝突判定（Falling.hlsl）
- Compute Shader により、粒子の生成、速度の積分、位置の更新を GPU 上で実行し、AliveList / FreeList で有効な粒子と再利用可能なスロットを管理
- 予測位置をワールド空間に変換し、ボクセル座標から Morton コードを生成して対応する三角形インデックスを検索することで、衝突判定の対象を絞り込み
- フレーム内の移動量からワールド空間のレイを構成し、その移動距離の範囲内で候補三角形との交差を判定
- 衝突時は表面法線方向にオフセットを加えて位置を補正し、速度をゼロにすることで、地形表面との接触応答を実現
- Geometry Shader で粒子をカメラに正対するビルボードに展開し、円形クリッピングと透明度のグラデーションで柔らかな外観を描画

### 水面描画（LakeSurface.hlsl）
- 方向と速度の異なる 2 枚のスクロールする法線マップを合成し、動きのある水面のディテールを生成
- Vertex Shader で法線マップをサンプリングして頂点を変位させ、Pixel Shader の法線の揺らぎと組み合わせて水面の起伏を表現
- `g_WaveStrength` により頂点変位の振幅と描画用法線の揺らぎを一括制御し、0 に設定すると頂点変位を無効化して平面法線を使用する、穏やかな表面状態に切り替え可能
- 視線方向と表面法線から Fresnel の重みを計算し、水の基本色とハイライト色の合成および透明度の調整に使用
- 定数バッファを通じて、水の色、波の強さ、Fresnel のバイアスと指数などを設定可能

### プロシージャルなレーザービーム（Laser.hlsl）
- CPU からワールド空間の帯状頂点を受け取り、長手方向と幅方向の座標を用いて Pixel Shader 内でビームの外観を生成
- Core、Body、Rim の 3 種類の輝度分布を組み合わせ、中心の明るい芯、ビーム本体、輪郭の光を表現
- 時間に応じた正弦関数で長手方向の輝度を変化させ、テクスチャをサンプリングせずに流れる模様を生成
- ビームの両端に滑らかな減衰を適用し、端点の硬い境界を緩和
- 色の輝度と透明度の重みを個別に計算し、最低限の透明度を確保して輪郭の視認性を維持；HDR 基本色、流速、中心の芯の鋭さを調整可能

### デカールシステム（Decal.hlsl）
- インスタンスごとに位置、サイズ、表面法線、回転角度、寿命を設定し、弾痕、爆発痕、ビームの接触痕などの表面表現に対応
- 表面法線からローカル座標基底を構築し、平面デカールを接触面に合わせて配置
- 表面法線と視線方向に応じて位置をオフセットし、接触面との Z-fighting を軽減
- 4×2 の Texture Atlas を使用し、インスタンスごとの UV オフセットでデカールの模様を選択
- 経過時間と寿命から透明度の減衰を計算し、痕跡を徐々にフェードアウト

### 弾道・効果範囲プレビュー（ProjectilePreview.hlsl）
- `g_RenderType` により、同一 Shader 内で弾道軌跡と半球状の範囲表示を切り替え
- 外部で生成した軌跡の頂点を受け取り、頂点法線の Y 成分を透明度の調整パラメータとして使用してグラデーションを表現
- 指定された衝突位置を中心に半球メッシュを配置・拡縮し、接触点付近の想定効果範囲を可視化
- 時間に応じた正弦関数で半球のサイズと透明度を変化させ、周期的な呼吸アニメーションを表現
- 衝突位置からの距離に応じて透明度を減衰させ、減衰範囲も半球の拡縮に追従
- 定数バッファを通じて、衝突位置、範囲サイズ、基本色、時間、描画タイプを一括設定

### ShaderGroup と粒子エフェクトの構成
- `ShaderGroup` 列挙体で関連するエフェクトの Shader とリソースをグループ化して管理
- バッチ描画と統一されたリソースバインド処理に対応
- `ParticleEffectRendererBase` が粒子エフェクトに共通する GPU Pipeline を抽象化し、シミュレーションと描画の共通基盤を提供：
  - `BufferSet` の生成と管理をカプセル化し、粒子用 `StructuredBuffer`、`SRV`、`UAV` などの GPU リソースを管理
  - `Update()` でリソースをバインドし、Compute Shader を Dispatch して Emit / Update などの GPU シミュレーションを実行
  - Pipeline の各段階におけるリソースのバインドとアンバインドを共通化し、読み書きの競合を回避
  - 描画用の粒子 Buffer を準備し、Compute Shader と Graphics Pipeline 間のリソース切り替えを管理
  - 抽象インターフェース `DrawParticles()` を提供し、派生クラスでビルボードや Flipbook などの具体的な描画方式を実装
- 各粒子エフェクトは基盤となる Buffer 管理と Compute Shader の実行制御を再利用し、固有のシミュレーションパラメータと描画処理を実装

## 敵AIシステム

###  EnemyManager 管理
- 全ての敵キャラクターは `EnemyManager` により一元管理。
- 敵の生成、削除、更新、描画を一括制御。

###  行動制御：ビヘイビアツリー
- 各敵キャラは個別の `BehaviorTree` を所持。
- ノードタイプ：
  - `Selector` ノード：複数の行動から条件を満たす最初の子ノードを実行。
  - `Sequence` ノード：すべての子ノードを順番に評価、途中で失敗したら中断。
- 実装済みノード例：
  - プレイヤー発見 → 追跡 → 攻撃
  - パトロール → プレイヤー発見 → 移動 → 攻撃
- 条件判断はプレイヤーとの距離、視野角、遮蔽物の有無等に基づく。
- アニメーションと連携し、状態に応じて攻撃モーション・待機・移動アニメーションを再生。

## 非同期アーキテクチャシステム

### 非同期タスクとシステム管理
- 全ての非同期タスクは統一された非同期システムで管理され、モデルやリソースの非同期ロードをサポート。
- タスクバインディング方式：
  - `DeferredTaskBinder<T>`：クラスメソッドをバインドできる構造化タスク。
  - `RawDeferredTask`：関数ポインタやラムダ式による柔軟なタスク実装が可能。

### スレッドプール機構
- 自作の `ThreadPool` を使用してスレッド再利用を実現。
- Win32 の `CreateEvent` により、タスクの完了待機と通知を制御。
- 優先度付きタスク、遅延タスク、TaskOptions 等にも対応。

###  スレッドセーフ対応
- 軽量スピンロック `SpinLock` と `LightweightMutex` を実装。
- Octree 構築処理にロックを導入し、マルチスレッドセーフを確保。

###  モデル非同期ロード
- モデルロードは複数ステップに分割：
  1. サブスレッドで `.obj` / `.fbx` を解析
  2. メインスレッドで GPU リソースを作成
  3. DeferredTask の完了通知でモデルを初期化

###  テクスチャの非同期ロード
- 読み込みとアップロードを分離：
  - サブスレッド：ファイルを読み込んで `TextureUploadQueue` に追加
  - メインスレッド：`WaitForSingleObject` で完了を待ち、SRV を作成
- タスク完了後にコールバックでロード済みカウントを更新。
- 複数タスクをロックで同期してリソースの安全な処理を保証。

## UI システム（アニメーションとシーン統合）

###  UIAnimatedSprite によるアニメーション再生
- UI フレームアニメーション用の `UIAnimatedSprite` を追加。
- Texture Sheet による連番再生、ループ、フェード自動制御に対応。

###  フェード演出管理（ScreenFader）
- フェード処理を `ScreenFader` に統合。
- `UIOverlayRenderer` + alpha ブレンドで暗転演出を制御。
- 自動フェードイン・アウト API を提供し、全てのシーン切替と連携可能。

###  ローディングシーン（UILoadingScene）
- ロード中に表示される専用 UI シーン。
- 内部状態機で時間や進行度に応じてアニメ制御：
  - 入場 → ロード → 完了 → 退場のアニメーションシーケンス

###  タイトル画面（UITitleScene）
- タイトルロゴ・ボタン・アニメ等を統合したタイトル専用シーン。
- Enter キーでフェードアウト → ゲーム本編へ遷移。

###  Scene と GameMode の切替
- `Scene` クラスを拡張し、SceneID ごとのモデルリソース管理を導入。
- GameMode 切替時に旧シーンのモデルを破棄し、新シーンのモデルを非同期ロード。
- GameObject 登録・破棄 API を統一し、管理を一元化。


## ゲーム中枢制御

###  GameSystem クラスとリソースロード
- GameMode（タイトル / ローディング / ゲーム）ごとにリソースセットを管理。
- 各モードに応じて必要なモデル・テクスチャ・UI を非同期でロード。
- リソースの準備完了後にモード切替を通知し、シーン遷移を実行。
- モード終了時に該当リソースを自動解放し、無駄なメモリ消費を防止。
- タイトル / ローディング / ゲームなどの各 GameMode に応じたリソースの事前ロードと解放をサポート。
- 各モードには対応するリソースセット（モデル、テクスチャ、UI）があり、非同期ロードシステムで段階的に管理。
- モード切り替え時に非同期タスクを発行し、完了後にメインスレッドへ通知してシーン遷移を実行。
- モード終了時には該当モードで登録された GameObject を自動的に解放し、メモリ消費を抑制。
- ImGui による Debug ウィンドウ、CSM 設定切替、BoundingBox 表示制御。
