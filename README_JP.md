## レンダリングシステム

### 🎨 Forward Rendering
- Forward パスベースの描画。
- 複数のレンダリングパスに分離：
  - メインパス（Main Pass）
  - シャドウマップパス（Shadow Pass）
- 対応オブジェクトタイプ：
  - 静的モデル（Static Mesh）
  - スキンメッシュ（Skinned Mesh）
  - インスタンシング描画オブジェクト

### 🌘 シャドウマップシステム（CSM 対応）
- 最大4層までのカスケードシャドウマップに対応。
- LightViewProj 行列を自動計算。
- texel 単位での snap による精度調整。
- Debug 用 Frustum 可視化。
- ShadowMapRenderer が VS / Layout を自動切替。
- オブジェクトの AABB を用いたレベル選択と冗長アップロード対応。

## インスタンシング描画

### 🌱 対応オブジェクト
- 草（風で揺れる）
- 木（揺れ無し）
- 岩・花・茂み（今後対応予定）

### 🧩 技術的詳細
- オブジェクトごとに別の `InstanceBuffer` と `InputLayout` を使用。
- 草の頂点データは `GrassVertex` で、風揺れ用の `Weight` を保持。
- インスタンスごとにスケール・回転行列・位置情報を `InstanceData` に格納。
- アップロード方式：`D3D11_USAGE_DYNAMIC + Map/Unmap`。
- カリング済みデータは `SimpleArray<InstanceData>* visibleInstances` に格納。

### 🌀 LOD（Level of Detail）対応
- LOD レベルごとにバッファを分割管理。
- 各フレームでカメラとの距離から LOD レベルを自動決定。
- `DrawIndexedInstanced()` を LOD ごとに実行。

## モデル読み込みとアニメーション管理

### 📁 FBXLoader の実装
- 自作の `FBXLoader` により `.fbx`（ASCII形式）ファイルを直接パース。
- 頂点情報（Position, Normal, UV, Tangent 等）、インデックス、マテリアルを抽出。
- スケルトン構造：各ボーンに対する階層構造・親子関係を保持。
- アニメーションデータ：
  - ボーンごとのキーフレーム（位置・回転・スケール）を取得。
  - 複数のアニメーションクリップを `AnimClip` として格納。
  - 各 `AnimClip` に対して長さ、ループ属性、ブレンド用補間情報を保持。
- アニメーションクリップはアニメーションステートマシンに連携され、状態に応じて切り替え・ブレンド処理を実施。


### 🎭 状態遷移設計
- `AnimationStateMachine<State>` テンプレート構造。
- 列挙型 State による高速ステート管理。
- 各ステートにアニメーションデータ + 遷移条件 + 遷移後ステート + ブレンド時間保持。

### 🔄 遷移条件の実装
- 関数ポインタ（`bool (Character::*)() const`）で条件分岐。
- `GetNextState(ISkinnedMeshModelChar* character)` にキャラ参照を渡すことで、内部状態による判断可能。

### 💫 補間・ブレンド
- 直線補間：`XMVectorLerp`（位置）
- 球面線形補間：`XMQuaternionSlerp`（回転）
- ブレンド中のボーンマトリクス合成処理あり。

## パーティクルシステム

### 🔥 完全 GPU ベースの構成
- 全ての処理を Compute Shader により実装。
- 4段階パイプライン：
  - `EmitCS`: 粒子の生成
  - `UpdateCS`: 粒子の位置・速度・寿命更新
  - `SortCS`: 描画順用ソート（アルファ対応）
  - `DrawIndirect`: `IndirectArgs` による描画

### 🧠 粒子管理方式
- `FreeList` 構造：死亡した粒子の回収と空き SlotID の再利用。
- `g_FreeListConsumeUAV.Consume()` により動的割り当て。
- `spawnRate` による生成速度の統一制御。

### 🌈 機能一覧
- **フレームアニメーション（Texture Sheet / Flipbook）**
- **Cone 形状からの発射エリア制御**
- **Lifetime に応じたスケーリング・色変化**
- **SoftParticle 対応（カメラ距離によるフェード）**
- **DrawIndirect + GPU ソートによる高効率バッチ描画**

## 地形・衝突管理

### 🧱 Octree（八分木）による空間分割
- 地形三角形の高速検索用 Octree を使用  
- 各ノードは AABB、子ノードポインタ、三角形インデックスを保持  
- **動的構築・破棄**に対応  
- **非同期構築**により、マルチスレッドで遅延構築し、メインスレッドの負荷を軽減

### 🧊 Voxel Grid 空間分割
- ハッシュテーブルと Morton 符号を使用したスパースボクセル構造  
- `VoxelKey`（整数座標）→ `MortonCode64` をハッシュキーとして使用  
- 各 `VoxelEntry` に三角形ポインタを格納、スレッドセーフな `SpinLock` 対応  
- GPU用に展開：  
  - `IndexTripletPageHeader` に各ページの Morton 符号、三角形数、開始インデックスを格納  
  - 三角形全体は `StructuredBuffer<Triangle>` にアップロード  
- GPU側の検索フロー：  
  - 位置から Morton 符号を計算 → バイナリサーチでページ検索  
  - ページ内の三角形とレイとの交差判定を実行  
- ✅ **SPH 粒子システムとの統合**：  
  - 各粒子は `UpdateCS` 内で次の移動を予測  
  - Voxel Grid 上で近傍の地形三角形を GPU 上で検索  
  - 距離・法線ベクトルを計算し、水面との衝突をリアルに再現  
  - 完全 GPU ベースで動作し、CPU 側とのデータ転送は不要 

### 🌾 草配置ロジック
- ランダムクラスター中心 + 半径内に複数草生成。
- クラスタ AABB → Octree → 近傍三角形リストを取得。
- Ray による地形交差点を取得して高さ決定。
- 三角形の法線に従って草を回転。
- 法線の傾斜角度によって設置を拒否。

## 水体パーティクル描画

水のシミュレーションはパーティクル駆動型で実装されており、すべての水面表現は流体パーティクルの集合によって構築されます。流れ、衝突、蓄積などのリアルな挙動をサポートします。炎や煙などの一時的なエフェクトとは異なり、水パーティクルは継続的な寿命を持ち、シーン全体との大規模な相互作用に対応します。

### 🌊 パーティクル発射ロジック（Emitter）
- 水パーティクルは `Emit()` インターフェースを通じて、Emitter によって毎フレーム発射されます。
- パーティクルは**継続的に存在する物理単位**であり、短時間で消滅することはありません。
- Cone や Box などの発射形状に対応し、初速度と初期位置が付与されます。
- `AliveList` により生存パーティクルを管理し、GPU 側では `DrawIndirect` により高効率に描画されます。

### 💡 SPH 流体システム

本システムは SPH（Smoothed Particle Hydrodynamics）に基づいています。各パーティクルは流体単位として重力・粘性・圧力などの力により移動・蓄積・衝突します。

空間インデックス構造には以下の2種類が対応しています：

#### ✅ Dense Grid（均一グリッド）
- 均一に分割されたボクセルグリッド
- 初期テストや粒子数が少ないケースに使用
- `FlattenIndex(x, y, z)` により1次元インデックスへ変換

#### ✅ Sparse Grid（スパースグリッド）
- 広範囲で疎な粒子分布に最適化された構造
- Morton 符号を用いて空間離散化とソートを実施
- すべての粒子検索と相互作用は GPU 上で完結

#### 🔁 SPH スパースグリッド構築フロー

各フレームにおいて、前フレームの生存パーティクルをもとにスパースな体素構造を構築し、近傍検索の高速化を図ります：

1. CPU 側で ReadBack により、前フレームの生存パーティクルを取得します。
2. 各パーティクルの位置から体素座標を計算し、`gridMin` を更新して負の座標を防止します。
3. 各体素に対して Morton 符号を計算し、`mortonMap` にパーティクル ID を追加します。
4. `mortonMap` の要素を `TempTriplet` に変換し、Morton 符号でソートします。
5. ソート済みのリストから `SPHIndexTriplet` を構築し、同じ Morton 符号の粒子をグループ化します。
6. `SPHIndexTriplet` から `PagedIndexTripletBuffer` を生成し、GPU にアップロードします。

> 次フレーム以降、GPU 側ではこの構造を用いて効率的な近傍検索と力計算を行います：

7. 各パーティクルは `prevPosition` を用いて、前回の体素と周囲の Morton 符号を逆算します。
8. `PagedIndexTripletBuffer` により近傍ページを探索します。
9. `g_SortedIndicesSRV` を参照して粒子インデックスを取得し、`g_ParticlesUAV` から粒子データを取得して、密度・圧力・粘性などの SPH 相互作用を計算します。

#### 🔬 SPH 力計算式（Pressure / Viscosity）

各フレーム、GPU は 3×3×3 の近傍探索を行い、SPH 力を計算します：

- **Wendland C2 カーネル関数** を用いて、粒子間の影響を重み付きで評価
- カーネル関数の重みを使って近傍粒子の質量を合計し、自身の密度を見積もります
- 圧力項は密度差とカーネルの勾配（`∇W`）で計算され、粒子の反発力を表します
- 粘性項は粒子間の速度差と `∇W` によりスムージングされます
- 最終的な力：
  - `pressureForce += -mass * (p_i + p_j) / 2ρ_j * ∇W`
  - `viscosityForce += viscosity * velDiff * mass / ρ_j * ∇W`
- さらに **XSPH 補正項** を加えて粒子速度を安定化させます：
  - `velocity += ε * Σ (neighbor.velocity - self.velocity) * W`

これらの計算はすべて Compute Shader によって実行され、近傍 Morton グリッド上の体素をループします。

#### 🧱 Voxel Grid + 三角形衝突検出

水パーティクルは、Voxel Grid を用いた三角形衝突判定により地形とのインタラクションを行います：

- 各フレーム、Morton 符号に基づいた稀疎構造の `VoxelGrid` を構築または再利用し、静的地形三角形を格納します
- 各パーティクルは `predictedPosition` から Ray を発射します
- `RayIntersectsTriangle()` により、周囲のボクセルに含まれる三角形との交差判定を実施
- 衝突時には、法線ベクトルに基づいて反射力や滑りを計算：
  - **貫通防止**：法線に沿って反射または滑り
  - **地面スライド**：法線接線方向の速度を保持し、垂直成分を除去
- これにより、自然な下流動作・縁の蓄積・容器内の循環などが再現されます

この処理は SPH 力計算と並列に実行され、統一された流体挙動を実現します。

### 🧊 液面再構築（Marching Cubes）

水パーティクルは離散的な存在のため、連続した液面を描画するには Marching Cubes により表面メッシュを再構築する必要があります。

#### 📐 スカラーフィールドの構築

液面再構築のための Scalar Field（スカラーフィールド）は以下の2方式に対応しています：

##### ✅ Dense Grid（均一ボクセル）
- 固定サイズの3D グリッドを確保
- 毎フレーム初期化後、再累積
- `FlattenIndex(x, y, z)` による配列インデックス化
- メリット：単純構造でデバッグしやすい
- デメリット：メモリ使用量が大きく、大規模空間には不向き

##### ✅ Sparse Grid（スパースボクセル）
- 粒子周辺のみを構築対象とするスパース構造
- 各粒子が影響半径内のボクセルに対してスカラ値を累積
- **64ビット Morton 符号** を使用し、超広範囲に対応
- **ボクセル中心の Pull 型（Voxel-Centric）構築方式**：
  - 各体素が周囲粒子を探索し、重み付きで値を加算
  - 重みは距離減衰を反映し、カーネルには **Wendland C2** を使用
- 出力結果は `StructuredBuffer<float>` として GPU にアップロードされ、`InterlockedAdd` により同時書き込み対応

この構築処理は `SPHSystem` と同じ Morton インフラ・ページング構造に対応しています。

#### 🧱 Marching Cubes メッシュ構築フロー

Scalar Field が構築されると、GPU 上で Marching Cubes により表面メッシュを生成します：

1. 各ボクセルセルにおいて、8 頂点の値が閾値を跨ぐかを判定
2. `g_TriTableSRV` を参照して三角形トポロジーを取得
3. 各辺の交点位置・法線を計算し、`VertexBuffer`・`IndexBuffer` に `InterlockedAdd` で書き込み
4. `DrawIndexedInstancedIndirect` を使用し描画、Cluster 分割による並列処理にも対応

重複頂点生成を避けるため、**Edge Vertex Cache** により辺のインデックスをキャッシュしています。

#### 💡 Thickness Map による液面シェーディング

液体表面の体積感とリアリズムを高めるため、スクリーンスペース厚みテクスチャ（Thickness Map）を併用しています：

- 水パーティクルの描画時に、その深度情報を厚みマップへ書き込み
- Marching Cubes で構築されたメッシュが描画時に厚みをサンプリングし、暗化や吸収表現を実現
- 以下のような演出が可能：
  - 半透明なエッジ
  - 深い領域での暗化
  - SoftParticle、境界ぼかし、泡のエフェクトなど

これらは `FluidThicknessRenderer` コンポーネントによって一括管理されています。

## 敵AIシステム

### 👾 EnemyManager 管理
- 全ての敵キャラクターは `EnemyManager` により一元管理。
- 敵の生成、削除、更新、描画を一括制御。

### 🧠 行動制御：ビヘイビアツリー
- 各敵キャラは個別の `BehaviorTree` を所持。
- ノードタイプ：
  - `Selector` ノード：複数の行動から条件を満たす最初の子ノードを実行。
  - `Sequence` ノード：すべての子ノードを順番に評価、途中で失敗したら中断。
- 実装済みノード例：
  - プレイヤー発見 → 追跡 → 攻撃
  - パトロール → プレイヤー発見 → 移動 → 攻撃
- 条件判断はプレイヤーとの距離、視野角、遮蔽物の有無等に基づく。
- アニメーションと連携し、状態に応じて攻撃モーション・待機・移動アニメーションを再生。

## 非同期アーキテクチャシステム

### 📦 非同期タスクとシステム管理
- 全ての非同期タスクは統一された非同期システムで管理され、モデルやリソースの非同期ロードをサポート。
- タスクバインディング方式：
  - `DeferredTaskBinder<T>`：クラスメソッドをバインドできる構造化タスク。
  - `RawDeferredTask`：関数ポインタやラムダ式による柔軟なタスク実装が可能。

### 🔁 スレッドプール機構
- 自作の `ThreadPool` を使用してスレッド再利用を実現。
- Win32 の `CreateEvent` により、タスクの完了待機と通知を制御。
- 優先度付きタスク、遅延タスク、TaskOptions 等にも対応。

### 🔒 スレッドセーフ対応
- 軽量スピンロック `SpinLock` と `LightweightMutex` を実装。
- Octree 構築処理にロックを導入し、マルチスレッドセーフを確保。

### 🧵 モデル非同期ロード
- モデルロードは複数ステップに分割：
  1. サブスレッドで `.obj` / `.fbx` を解析
  2. メインスレッドで GPU リソースを作成
  3. DeferredTask の完了通知でモデルを初期化

### 🖼 テクスチャの非同期ロード
- 読み込みとアップロードを分離：
  - サブスレッド：ファイルを読み込んで `TextureUploadQueue` に追加
  - メインスレッド：`WaitForSingleObject` で完了を待ち、SRV を作成
- タスク完了後にコールバックでロード済みカウントを更新。
- 複数タスクをロックで同期してリソースの安全な処理を保証。

## UI システム（アニメーションとシーン統合）

### 🎞 UIAnimatedSprite によるアニメーション再生
- UI フレームアニメーション用の `UIAnimatedSprite` を追加。
- Texture Sheet による連番再生、ループ、フェード自動制御に対応。

### 🌗 フェード演出管理（ScreenFader）
- フェード処理を `ScreenFader` に統合。
- `UIOverlayRenderer` + alpha ブレンドで暗転演出を制御。
- 自動フェードイン・アウト API を提供し、全てのシーン切替と連携可能。

### ⏳ ローディングシーン（UILoadingScene）
- ロード中に表示される専用 UI シーン。
- 内部状態機で時間や進行度に応じてアニメ制御：
  - 入場 → ロード → 完了 → 退場のアニメーションシーケンス

### 🏠 タイトル画面（UITitleScene）
- タイトルロゴ・ボタン・アニメ等を統合したタイトル専用シーン。
- Enter キーでフェードアウト → ゲーム本編へ遷移。

### 🔁 Scene と GameMode の切替
- `Scene` クラスを拡張し、SceneID ごとのモデルリソース管理を導入。
- GameMode 切替時に旧シーンのモデルを破棄し、新シーンのモデルを非同期ロード。
- GameObject 登録・破棄 API を統一し、管理を一元化。


## ゲーム中枢制御

### 🧠 GameSystem クラスとリソースロード
- GameMode（タイトル / ローディング / ゲーム）ごとにリソースセットを管理。
- 各モードに応じて必要なモデル・テクスチャ・UI を非同期でロード。
- リソースの準備完了後にモード切替を通知し、シーン遷移を実行。
- モード終了時に該当リソースを自動解放し、無駄なメモリ消費を防止。
- タイトル / ローディング / ゲームなどの各 GameMode に応じたリソースの事前ロードと解放をサポート。
- 各モードには対応するリソースセット（モデル、テクスチャ、UI）があり、非同期ロードシステムで段階的に管理。
- モード切り替え時に非同期タスクを発行し、完了後にメインスレッドへ通知してシーン遷移を実行。
- モード終了時には該当モードで登録された GameObject を自動的に解放し、メモリ消費を抑制。
- ImGui による Debug ウィンドウ、CSM 設定切替、BoundingBox 表示制御。
